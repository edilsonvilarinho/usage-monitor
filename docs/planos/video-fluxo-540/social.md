## LinkedIn (PT)

Como funciona um fluxo de desenvolvimento em que agentes de IA conduzem o trabalho do pedido ao merge?

No Usage Monitor, projeto de código aberto, um pedido em linguagem comum dispara tudo pela skill `usage-monitor-workflow`:

→ Issue com plano curto e plano detalhado no repositório
→ Worktree própria para cada trabalho, nunca a main
→ Agentes especializados implementam; a orquestradora valida com evidência própria
→ TDD: o teste falha na asserção antes do código existir
→ Pull request com merge automático
→ CI só do que mudou, com um único check obrigatório, o ci-ok
→ Parada de segurança: na quarta falha, o agente para e entrega o diagnóstico
→ Testes criados documentados como comentário na issue

Cada decisão fica registrada, e nenhuma entrega é aceita pelo relatório do próprio agente.

Caso real, issue #537: 24 testes novos, 3961 na suíte, 0 falhas, 212 de 212 linhas do diff cobertas, 0 incidências.
